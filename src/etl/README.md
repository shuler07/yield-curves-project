# Сбор и проверка кривых MOEX

Реализация S2-03: загрузить кривые за дату или диапазон, проверить данные
и сохранить CSV с исходными ставками в отдельном каталоге запуска.
Пропуски сохраняются как `NA`. Интерполяция и экстраполяция выполняются позже,
при загрузке в БД. Сценарии, коэффициенты
дисконтирования и запись в БД относятся к следующим задачам.

## Установка

Из корня проекта, в существующем виртуальном окружении:

```powershell
python -m pip install -r requirements.txt
```

Нужен установленный Google Chrome. Selenium Manager подбирает ChromeDriver;
для первого запуска может понадобиться доступ к сети для его загрузки.
Импорт модулей не запускает Chrome и не создаёт каталогов.

## Запуск

Все команды выполняются из корня репозитория:

```powershell
# Одна дата. Уникальный каталог создаётся в src/etl/downloads/.
python -m src.etl.parse --date 2026-10-30

# Диапазон включительно и явно заданный НОВЫЙ каталог.
python -m src.etl.parse --date-from 2026-10-27 --date-to 2026-10-30 --run-dir downloads/run-2026-10-27-30 --timeout 180

# Повторная проверка и объединение уже полученных файлов без браузера и сети.
python -m src.etl.merge --run-dir downloads/run-2026-10-27-30
```

Нужно передать либо `--date`, либо оба `--date-from` и `--date-to` в формате
`YYYY-MM-DD`. Перевёрнутый диапазон и неположительный/неконечный таймаут
отклоняются до запуска браузера. Указанный `--run-dir` не должен существовать:
каждый сбор создаёт свой каталог, исключая старые файлы и параллельную запись.
Для повтора обработки готового каталога используется команда `merge`.

`--timeout` — один общий бюджет получения всех файлов, а не отдельный бюджет
на каждый год. Ожидания страницы и скачиваний используют оставшееся время.
Это не принудительное завершение процесса: запуск Chrome/ChromeDriver и
закрытие браузера могут добавить время поверх этого бюджета.
Chrome закрывается в `finally`, включая ошибки и таймауты.

## Какой экспорт используется

На [странице архива MOEX](https://www.moex.com/ru/marketdata/indices/state/g-curve/archive/)
есть кнопка «Скачать данные за выбранный период» и отдельная кнопка выгрузки
всей истории. Сборщик использует выбранный период, указывая сразу все 12 сроков:
`0.25, 0.5, 0.75, 1, 2, 3, 4, 5, 7, 10, 15, 20` лет.

У формы есть ограничение диапазона: интервал можно выбрать внутри одного
календарного года от начальной даты. Поэтому запрос через границу года
разбивается на отдельные выгрузки. Текущий экспорт возвращает обычный CSV
с преамбулой `zcyc`, заголовком `tradedate;tradetime;period_...` и десятичными
запятыми. Загрузка всей истории для короткого диапазона не требуется.

Форма MOEX требует, чтобы начало было строго раньше окончания. Для одной даты
запрашивается также соседний день, затем локальный фильтр оставляет только
выбранную дату. Манифест сохраняет именно запрошенный пользователем диапазон.
Для первого дня архива используется следующий день, в остальных случаях —
предыдущий. Сбор доступен начиная с `2014-01-01`, как и архив MOEX.

Дополнительно даты фильтруются локально, до публикации CSV: строки за пределами
запрошенного диапазона не попадают в результат, даже если источник их вернул.
Это также позволяет повторно обработать архив всей истории. При объединении
поддерживаются CSV и ZIP с CSV; ZIP проверяются по CRC и читаются в памяти,
без распаковки путей из архива на диск.

Ожидание скачивания учитывает временные файлы Chrome, ненулевой размер и
стабильность файла. Каждый ожидаемый файл получается последовательно в рамках
общего дедлайна. На незавершённой загрузке итоговый CSV не публикуется.

## Каталог запуска

```text
run-2026-10-27-30/
  curve_2026-10-27_2026-10-30.csv   # исходный экспорт
  manifest.json                   # диапазон и точный список исходных файлов
  merged_zcyc_ranges.csv           # все 12 сроков; пропуски отмечены NA
```

Манифест записывается после получения всех файлов. Само его наличие означает,
что файлы получены, но не гарантирует корректность их содержимого: успешный
результат — итоговый CSV и нулевой код возврата команды. Наличие `NA` не считается
ошибкой сбора; команда явно сообщает о недостающих сроках.
При ошибке исходные файлы остаются для диагностики и повторной обработки.
Файлы, не перечисленные в манифесте, не читаются.

Пример манифеста:

```json
{
  "version": 1,
  "source_url": "https://www.moex.com/ru/marketdata/indices/state/g-curve/archive/",
  "export_mode": "range",
  "date_from": "2026-10-27",
  "date_to": "2026-10-30",
  "files": ["curve_2026-10-27_2026-10-30.csv"]
}
```

Для ранее скачанных ZIP можно создать такой же манифест с нужным диапазоном,
`export_mode: "history"` и перечислением всех исходных ZIP в `files`.
Файлы должны лежать непосредственно в этом каталоге. Выход за его пределы,
пропущенные файлы и повторяющиеся пути отклоняются.

## Проверки и результат

- Проверяются заголовок, ожидаемые сроки, число колонок, дата, время котировки
  и числовые значения. Бесконечности, нечисловой мусор, неизвестные и повторяющиеся
  сроки отклоняются с указанием файла и строки. Повреждённые строки, где число
  ячеек не соответствует заголовку, не сдвигаются и не угадываются.
- Для каждого сочетания даты и времени в `merged_zcyc_ranges.csv` всегда
  записываются все 12 сроков. Отсутствующие колонки сроков, пустые ставки
  и маркеры `NA`, `N/A`, `NULL`, `NaN` приводятся к `NA`.
  Неполный снимок сохраняется. Ноль — настоящая ставка, а не признак пропуска.
- CSV сохраняется и при одной известной ставке, и если все ставки снимка
  отсутствуют, но его дата и время присутствуют. Никакие расчётные ставки
  в CSV не подставляются. Заполнение пропусков — задача будущего загрузчика БД;
  он должен распознать `NA` и восстановить ставки по согласованной методике
  перед записью обязательных числовых полей. Сам маркер `NA` в БД не записывается.
- Одинаковые численно дубли допустимы. Разные ставки для одной даты, времени
  и срока считаются конфликтом и приводят к ошибке.
- При полном отсутствии наблюдений за диапазон возникает `NoDataError`.
  Если данные есть только за часть дат, отсутствующие даты выводятся явно.
  Они не заполняются предыдущей кривой. Решение о выходных/праздниках — S2-06.
- Итог сортируется по дате и времени, колонки — по срокам. Сохраняются все
  внутридневные снимки, включая снимки с пропусками; правило ежедневного снимка
  остаётся в S2-01.
- Значения обрабатываются как `Decimal`, без округления. Ставки остаются
  **в процентах, как в исходном CSV MOEX**; десятичный разделитель результата —
  точка. Преобразование в доли единицы для БД относится к расчётному слою/загрузчику.
- CSV записывается во временный файл и атомарно заменяет результат
  после завершения записи. Ошибка проверки структуры/ставок не заменяет прошлый
  merged CSV.

Будущий загрузчик БД получает `merged_zcyc_ranges.csv` с исходными наблюдениями
и явными пропусками. До восстановления пропусков такой файл нельзя считать
полной числовой кривой для расчётов. Формат колонок:

```csv
tradedate;tradetime;period_0.25;period_0.5;period_0.75;period_1;...
```

Коды завершения CLI: `0` — CSV сформирован, в том числе со ставками `NA`;
`1` — ошибка источника, файла, валидации или отсутствие наблюдений за диапазон;
`2` — неверные параметры команды.
Для программного вызова доступны `collect_curves(DateRange(...), run_dir, timeout)`,
`merge_run(run_dir)` и `extract_and_merge(files, output_file, dates)`.
Результат содержит путь к файлу, число снимков, даты без наблюдений
и `incomplete_snapshots` с отсутствующими сроками. CLI выводит список пропусков.

## Проверки разработки

```powershell
python -m pip install -r requirements-dev.txt
pytest tests/etl -q
```

Тесты не обращаются к MOEX и не запускают браузер: проверяют реальный образец
формата MOEX, повреждённые/неполные данные, CRC архивов, фильтрацию дат, изоляцию
запусков, общий таймаут, завершение браузера и атомарную публикацию результата.
`tests/etl/fixtures/moex_range.csv` — небольшой экспорт MOEX за 27–30.10.2026,
полученный со страницы архива 31.10.2026.
